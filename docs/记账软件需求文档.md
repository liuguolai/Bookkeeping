# 单机多币种记账软件需求文档

版本：0.2 评审稿  
更新日期：2026年9月30日  
适用对象：产品、设计、开发、测试及项目负责人

本文定义一款支持安卓和 iOS 的单机记账 App，以快速记账、分类统计、预算、备份为核心。全部账务功能在手机本地运行，无需业务服务器或注册登录。支持人民币、港币等多种货币，每种货币分别统计和设置预算，不提供汇率换算或跨币种金额合计。

## 一 已确认方向与建议默认值

### 已确认方向

| 项目 | 用户已确认的要求 |
| --- | --- |
| 平台 | 手机 App，目标覆盖安卓和 iOS |
| 运行方式 | 单机记账，无需业务服务器 |
| 核心功能 | 简单易用，支持快速记账、分类统计、预算、备份 |
| 多币种 | 支持人民币、港币等多种货币 |
| 统计与预算 | 按币种分别统计和设置预算，不做汇率换算 |
| 账户余额 | 只记录收支，支付方式选填，暂不管理账户余额 |

### 建议默认值

以下为产品设计建议，不代表用户已经逐项确认。

- 界面使用简体中文，首次默认币种为人民币；创建账本时可以调整。
- 保留本地多账本，例如日常、家庭、旅行。家庭开销由使用这部手机的人记录，不提供成员角色和共享权限。
- 同一账本允许记录多种币种，使用时可设置默认币种及常用币种。
- 首版预置人民币、港币、澳门元、美元、欧元、英镑、日元、新加坡元。除人民币和港币外，其余为建议清单，可在原型评审时调整。
- 单部手机建议最多创建 20 个账本，首版性能以每账本 10000 条流水为基础。
- 采用自然月预算，账本时区创建时默认 Asia/Shanghai，首次创建允许选择，创建后暂不提供修改入口。
- 普通流水回收站保留 30 天，整本删除提供 7 天撤销期。保留期为可调整的产品规则。
- 首版无广告、收费墙、社交排行和理财推荐。

## 二 产品目标与首版范围

### 产品目标

1. 熟悉操作后，约 10 秒内完成一笔普通收支记录。
2. 看清每种币种的收入、净支出、结余、主要消费分类及预算使用情况。
3. 飞行模式下可以首次启动、记账、查询、统计、备份和恢复本地文件。
4. 支持误删恢复和手动换机迁移，避免用户误以为数据已经保存到云端。

“约 10 秒”是可用性目标，需实测验证。无需业务服务器不等于没有研发、分发或上架成本。

| 场景 | 用户动作 | 预期结果 |

| 香港消费 | 同一账本记录港币交通支出 HKD 30.00 | 只更新港币统计与港币预算 |
| 同日多币种 | 记录 CNY 100.00 和 HKD 100.00 | 分别展示，不显示金额总计 200 |
| 家庭支出 | 在本地家庭账本记录日用品费用 | 该手机可查询，不发送给其他成员 |
| 旅行记账 | 临时改用日元录入 JPY 1200 | 使用整数金额，原有人民币记录不变 |
| 跨月退款 | 九月消费 HKD 200，十月退 HKD 50 | 九月支出不回写，十月港币支出冲减 50 |

## 四 页面与交互

底部设置“明细”“统计”“预算”“设置”四个页面，提供醒目的“记一笔”入口。

| 页面 | 主要内容 |
| --- | --- |
| 首次使用 | 本地数据说明、创建账本、选择默认币种、记录第一笔 |
| 明细 | 当前账本、月份、币种筛选、分币种收支摘要、按日分组流水 |
| 记一笔 | 收支类型、金额、币种、分类、日期、支付方式、备注、目标账本 |
| 流水详情 | 金额及币种、分类、发生时间、修改时间、编辑、删除、退款 |
| 统计 | 单一币种选择、日期范围、分类排行、趋势、下钻明细 |
| 预算 | 单一币种选择、总预算、已用、剩余、分类预算 |
| 设置 | 账本管理、常用币种、分类、支付方式、导出备份、回收站、数据清除 |

### 快速记账

打开 App → 点击记一笔 → 输入金额 → 选择分类 → 保存。

- 默认支出和今天，使用当前账本默认币种；币种选择入口紧挨金额，始终显示代码。
- 临时选择外币只影响当前记录，不自动修改账本默认币种。改变默认币种需在账本设置中操作。
- 金额、币种、分类必填；支付方式和备注选填。分类首次不预选。
- 选择“全部币种”查看明细后新增记录，仍使用账本默认币种，不能猜测要记哪一种。
- 在单币种明细视图点击“记一笔”，建议沿用该筛选币种，并明确显示；从其他页面进入使用账本默认币种。
- 保存成功后提示“已保存到本机”，刷新相关明细、统计、预算。补记历史时展示所在日期，不把历史流水永久置顶。
- 连续点击保存只生成一笔。失败时保留输入，不显示成功反馈。
- 离开未保存表单时可继续编辑、保存草稿或放弃；草稿按账本隔离并保留币种。
- 表单内更换币种时说明“仅更换币种，不换算金额”；若已有金额，保留原输入供确认。精度不合法时阻止保存，不自动四舍五入。
- 切换账本时不得把草稿自动写入新账本。

## 五 多币种规则

### 内置币种与名称

| 界面名称 | 内部代码 | 首版允许小数位 | 状态 |
| --- | --- | --- | --- |
| 人民币 | CNY | 2 | 用户明确要求，RMB 作为搜索别名 |
| 港币 | HKD | 2 | 用户明确要求 |
| 澳门元 | MOP | 2 | 建议预置 |
| 美元 | USD | 2 | 建议预置 |
| 欧元 | EUR | 2 | 建议预置 |
| 英镑 | GBP | 2 | 建议预置 |
| 日元 | JPY | 0 | 建议预置 |
| 新加坡元 | SGD | 2 | 建议预置 |

内部统一使用币种代码，不把 RMB 与 CNY 创建成两种币种。币种维护依据参考 [SIX 的 ISO 4217 官方维护资料](https://www.six-group.com/en/products-services/financial-information/market-reference-data/data-standards.html)；内置表随 App 发布，不在启动时联网获取。

金额统一使用“代码 + 金额”展示，例如 CNY 100.00、HKD 100.00、JPY 1200；可以附加符号，但不单独用 ¥ 或 $ 区分货币。币种选择支持中文名称和代码搜索，人民币额外匹配 RMB。

### 存储与输入

- 每笔流水必须保存独立的币种代码；账本默认币种仅影响新记录预填值。
- 金额按该币种最小单位存为整数，并关联精度定义。例如 CNY 28.50 存为 2850，JPY 1200 存为 1200。
- 不将所有金额统一理解为人民币“分”，不使用浮点数直接累计金额。
- 每笔金额大于零，小于 100000000 个该币种主单位；人民币最高 99999999.99，日元最高 99999999。预算金额沿用同样的单项限制。
- 小数位超过当前币种允许值时拒绝保存，不静默截断或取整。日元键盘不显示小数点，粘贴的小数输入也要校验。
- 先精确解析金额字符串，再转最小单位整数；报表汇总使用足够范围的精确整数，不能受单笔上限限制或整数溢出影响。
- 首版不允许用户随意创建币种代码或修改既有币种精度。新增币种由后续版本维护，不能改变历史金额含义。

### 常用币种与修改

常用币种只控制新建表单的快捷排序，不限制历史查看。默认币种必须在常用列表中；移除默认币种时要求先选择替代默认值。移除某个常用币种不会删除其流水、预算、筛选入口或影响历史退款。

编辑已保存流水时不允许直接修改币种；记错币种需删除后重新记录。其他字段仍可正常编辑。此规则避免把既有金额误当成已按汇率换算。

### 汇总边界

- 混合币种明细可同时列出不同币种记录，每笔显示代码。
- 月摘要与每日小计按币种分组；“全部币种”只表示全部记录，不代表统一金额。
- 可以显示总记录数，不得显示跨币种收入、支出、结余或平均消费金额。
- 分类排行、趋势图和占比每次只分析一种币种；不同币种不能共享一个金额排行榜或合并堆叠金额。
- 默认币种没有记录时显示该币种空态，并提示其他币种有记录，不能用零金额暗示整个账本无数据。
- 预算切换和统计切换均明确标出币种，分类下钻沿用当前币种与日期范围。

## 六 流水 分类与检索

### F03 收支流水字段

| 字段 | 规则 |
| --- | --- |
| 唯一标识 | 本机生成，连续点击与失败重试复用同次操作标识 |
| 账本 | 必填，不能写入已归档或待删除账本 |
| 类型 | 收入、支出；退款从原支出创建 |
| 金额与币种 | 必填，执行第五节精度和范围规则 |
| 分类 | 收入和支出必填，退款继承原支出分类 |
| 发生时间 | 可补记历史，不能晚于账本时区的今天，默认当前时间 |
| 支付方式 | 选填，例如微信、支付宝、银行卡、现金、其他 |
| 备注 | 选填，最多 200 个字符，支持中文与表情 |
| 创建与修改时间 | 系统记录，和发生时间分开 |
| 退款关联 | 退款必须关联同账本同币种的原支出 |

无云账号或录入人字段，不根据本地记录推断家庭成员出资或欠款。

编辑金额、日期和分类后重新计算受影响月份的统计及预算。已有退款的原支出不能减至已退款总额以下；修改分类时关联退款采用新分类。收入和支出类型不可直接互换，需删除后重建。

首版不提供已有流水跨账本移动。删掉存在有效退款的原支出时，列出关联退款并确认成组删除；成组恢复不得断开关联。单独删除退款仅撤销这笔退款的影响。恢复单独退款时需重新校验原支出状态、日期和剩余可退金额，不得因恢复造成超退。

### F04 分类和支付方式

默认支出分类：餐饮、交通、购物、住房、生活缴费、医疗健康、教育、娱乐、旅行、人情往来、其他支出。默认收入分类：工资、奖金、兼职、其他收入。

- 使用单层分类，支持新增、重命名、图标、排序、停用。
- 分类属于账本，同一账本各币种共用分类；统计时始终按币种拆开。
- 相同账本、相同收支类型内分类名不可重复，比较前去除首尾空格。
- 已被流水引用的分类只能停用，不能删除；历史仍显示。重命名作用于该分类全部历史。
- 支付方式仅为标签，不展示卡号、余额、绑定或扣款能力；已引用项只能停用。
- 停用项不能用于新的普通流水，但历史记录仍可展示，同币种退款可继承原分类和支付方式。

### F06 检索

支持自然月、自定义日期范围，以及类型、币种、分类、支付方式、备注关键词的组合检索，范围仅限当前账本。

按发生时间倒序排列，同一发生时间按创建时间和唯一标识稳定排序。区分账本无记录、当前币种无记录和筛选后无结果。按日小计与筛选汇总均保留币种维度。

## 七 本地账本与日期

账本名称 1 至 20 个字符。默认创建“日常账本”，可自行新增家庭、旅行等账本；这些名称不形成权限等级。使用同一 App 实例的人可以访问其中全部账本，账本分类不等于隐私隔离。

支持创建、重命名、归档和解除归档。归档后流水与预算只读，仍可查询、导出和备份；归档月份后的新预算不自动创建，解除归档后可手动复制最近一月预算。

日期归属依据账本创建时确定的时区，统计按发生日期归属月份。记录的当地日期和时间上下文需保存，旅行、更换手机时区或恢复备份不能把旧记录自动移动到另一天或另一个月。

账本设置中修改默认币种，只影响新建记录的默认选择；所有历史流水、预算、退款保持原币种。切换账本时，明细、统计、预算一起切换数据范围。

删除账本需输入名称确认，建议进入 7 天撤销期，期间只读；到期后在下次启动或维护时清理。撤销恢复该账本剩余未过期数据，过期流水不因此自动复活。彻底删除前建议导出备份，首版不提供跨账本合计或重复消费检测。

## 八 统计与预算

### F07 统计口径

以下公式仅在同一账本、同一币种、同一时间范围内成立。回收站数据不参加统计。

| 指标 | 定义 |
| --- | --- |
| 收入 | 收入流水金额之和，不含退款 |
| 原始支出 | 支出流水金额之和，未扣退款 |
| 退款 | 期间实际发生的退款金额之和 |
| 净支出 | 原始支出减退款，可为负 |
| 收支结余 | 收入减净支出，不代表钱包或银行卡余额 |
| 分类净支出 | 当前分类的支出减同期该分类退款 |

首页显示“净支出”，支持展开原始支出与退款。统计提供月度、年度和自定义区间、分类条形图、趋势及下钻明细。负净支出使用可显示负数的条形图，不生成错误饼图或虚假百分比。

例如当月收入 CNY 8000、支出 CNY 2000、收入 HKD 1000、支出 HKD 300，则分别显示人民币结余 CNY 6000、港币结余 HKD 700；没有两者相加的总金额。

### F08 按币种月度预算

- 预算唯一范围为“账本 + 自然月 + 币种”。人民币和港币预算各自独立，可只设置其中一种。
- 每个币种有一个总支出预算，可给部分支出分类设置子预算；同币种分类预算之和不得超过该币种总预算。
- 预算金额必须大于零，并满足对应币种精度。降低总预算时必须仍覆盖已分配分类预算之和。
- 允许预算低于已发生净支出，保存后显示超支。
- 已用预算 = max(0，同币种本月净支出)；剩余预算 = 总预算减已用，允许为负。
- 分类预算使用同样的计算方法。分类各自取零下限可能造成其已用之和不等于总预算已用，界面说明，不强行画成堆叠图。
- 未设置预算的币种显示“设置本月港币预算”等提示，不借用人民币额度，也不显示 0%。
- 使用率达到 80% 提示接近预算，达到 100% 提示已用完，超过 100% 展示超支金额。
- App 内阈值提醒按账本、月份、币种、总预算或分类、阈值去重。退款后更新进度，不重复弹窗。
- 新月首次进入账本时，逐币种继承最近一个已有预算月的配置；长时间未使用时不补建中间月份预算。
- 继承时跳过停用分类，其金额留在该币种总预算未分配部分，并提示用户。归档账本不继承。
- 修改某月某币种预算不会修改历史月份或其他币种预算；不能把既有预算直接改为另一币种。

## 九 退款和特殊收支

### F09 同币种退款

退款关联同一账本的有效支出，继承其币种与分类，不显示可编辑的币种选择。可以分多次退款，有效退款之和不得超过原支出金额。

退款发生日期不得早于消费日期或晚于今天。金额默认剩余可退金额，支付方式默认沿用原支出，可手动修改。

跨月退款计入退款发生月份，原月份不回写。例如九月支出 HKD 200，十月全退且无其他流水，则九月港币净支出为 HKD 200，十月为 HKD -200，十月港币预算已用为 0，人民币预算不受影响。

详情展示原支出、已退款、尚未退款，三者币种一致。删除、恢复和修改退款均重新校验约束，在同一笔本地数据库事务中完成。

跨币种退款首版不自动核算。若实际收回的币种不同，提示当前仅支持原币种退款，不按相同数字关联，也不偷偷填汇率；如用户选择将实际到账另记该币种收入，需明确它会影响收入统计且不会冲销原支出。

### 其他边界

本人账户间转钱、提现、换汇均不作为日常收入或消费重复记账；换汇手续费可以按实际支付币种记为支出。外币消费只记录一次，优先使用用户选择跟踪的消费币种，不同时记录原币金额和银行卡折算扣款作为两笔消费。

家庭内部转钱不与最终购物消费重复计入家庭开销。借贷本金、信用卡账务、余额对账不在首版核算范围，帮助中应说明。

## 十 本地可靠性与数据隐私

### F10 本地持久化

- 首次启动、创建账本、记录、查询、预算、导出及恢复本地文件均不依赖网络。
- 只有数据库事务提交成功后才显示“已保存到本机”；App 崩溃、杀进程或设备重启后已提交记录仍可读。
- 重复点击、重复回调和保存失败重试不得创建重复记录。
- 金额及关联修改在一笔事务内提交，退款不得出现半写入或超退；编辑失败时保留原数据和用户输入。
- 磁盘空间不足、数据库异常、备份中断均显示具体原因，不暗示已成功。
- 版本升级需有数据库迁移与失败回滚方案，迁移前生成本地保护快照；该快照不是可替代外部备份的永久副本。
- 页面没有“已同步”“待同步”或云端安全保存等状态。

### F12 隐私与删除

- 账务数据存放在 App 私有存储，首版不上传流水、备注、预算或使用行为，不加入依赖自有服务的统计功能。
- 不申请联系人、短信和定位权限。文件导入导出通过系统文件选择入口完成，不要求扫描整个文件系统。
- 本地数据库及备份采用适当的加密保护；设备本地密钥使用系统安全存储，备份密码不得写入普通配置和日志。
- 系统级云备份与设备迁移需在安卓和 iOS 分别核对；首版默认排除账务数据库的自动云备份，不把平台机制当成产品恢复保证。
- 导出的 CSV 是明文；导出前说明。只有加密备份受备份密码保护。
- 普通流水删除进入本地回收站，建议保留 30 天；过期后在 App 下次运行时清理，不依赖后台持续运行。
- 清空全部数据需要明确二次确认，并提供先备份入口；确认后删除所有账本、草稿、回收站、内部快照、索引和相关本地密钥。
- 用户另存的 CSV 或备份文件不会随 App 清空自动删除，界面说明外部副本需自行管理。
- App 卸载、手机遗失、损坏或本地数据被清除后，只有可用的外部备份能用于本产品的恢复流程；没有云端找回功能。
- 单机多账本不提供家庭成员间隐私隔离，敏感数据依赖设备访问保护，应用锁列为后续增强。

## 十一 导出 备份与换机

### CSV 导出

支持导出单个账本的指定日期和币种范围；选择全部币种时包含独立币种列，不产生混合金额总计。

字段至少包含流水标识、账本名称、类型、发生日期和时间、账本时区、金额十进制文本、币种代码、分类、支付方式、备注、关联原支出标识。退款以正金额和独立类型导出。

正确处理中文、逗号、换行和可能被表格软件作为公式执行的文本。选择的时间范围若只包含退款而不包含原支出，保留关联标识并说明原支出不在本次范围内；CSV 用于查看和分析，首版不作为恢复格式。

### 加密备份

- 支持备份单个账本或全部未处于删除撤销期的账本，包含已归档账本；导出前显示实际范围。
- 包含有效流水、分类、支付方式、各币种预算、币种及精度元数据、默认和常用币种、账本时区、退款关系。
- 不包含回收站、未保存草稿、内部迁移快照和诊断日志。界面明确备份范围，不称其为手机完整镜像。
- 从本地一致性快照生成备份，生成期间的新流水不混入已固定快照，文件标明截止时间。
- 用户设置并确认备份密码，再通过系统文件入口选择保存位置；加密与完整性校验必须同时满足。
- 备份密码无法找回。每次保存结果准确区分文件生成、系统保存成功、取消或失败；若平台无法确认接收方落盘，只提示“已交给系统保存或分享”，不能报外部保存成功。
- 展示最近备份时间、备份范围以及此后是否发生修改；单个账本备份不能标记全部账本已备份。
- 有数据但从未备份时提示一次；建议超过 7 天且有未备份修改时，在 App 内温和提醒，用户可暂缓。
- App 私有目录里的临时备份不能当作防卸载备份。建议用户保存到手机外的电脑或自行选择的网盘位置。
- 备份生成、校验和读取本地文件均可离线；选择第三方云盘文件位置时能否离线由该存储服务决定，App 不直接接入其账号或接口。

### 恢复流程

选择文件 → 输入密码 → 校验格式与完整性 → 展示账本、时间、条数及分币种汇总 → 确认恢复为新账本 → 核对结果。

- 不覆盖现有账本，不合并不同设备记录。多人各自维护的文件不能通过恢复自动变成共享账本。
- 全部账本备份在一次操作中恢复成一组新账本，同名时添加“恢复副本”等后缀。
- 重新分配运行标识，保留来源标识，完整映射分类、预算与退款关系。
- 保持原币种、精度、发生日期、时区、预算月份和归档状态，不改成恢复时的默认值。
- 重复恢复相同备份指纹时提示已存在副本，用户可查看或明确另建。
- 密码错误、文件损坏、不支持的版本或币种、金额精度非法、引用断裂时整份拒绝；不猜测币种，不自动舍入，不静默跳过记录。
- 恢复中断或空间不足时整体回滚，不留下可见半成品；现有数据保持不变。
- 安卓与 iOS 使用同一备份格式和兼容规则，必须验证双向迁移。不能绑定源设备密钥导致新手机无法解密。
- 恢复成功显示实际账本数、流水数和分币种核对结果。此后两台设备各自独立，不自动同步。

## 十二 数据模型与非功能要求

### 核心数据对象

| 对象 | 关键字段与约束 |
| --- | --- |
| 本地设置 | 常用币种、当前账本、备份提示状态，无账号凭据 |
| 币种定义 | 代码、中文名、别名、符号、精度、定义版本 |
| 账本 | 唯一标识、名称、默认币种、常用币种、时区、归档及删除状态 |
| 流水 | 唯一标识、账本、类型、金额最小单位整数、币种、发生时间、分类、支付方式、备注、删除状态 |
| 退款关系 | 同账本同币种关联，原支出有效，累计不超限 |
| 分类和支付方式 | 所属账本、名称、排序、停用状态 |
| 预算 | 账本、月份、币种、总预算、分类预算；三个维度组成唯一范围 |
| 草稿 | 所属账本、币种、金额文本、输入字段，不参与报表 |
| 备份元信息 | 文件版本、指纹、快照时间、范围、币种定义、条数、完整性信息 |
| 来源映射 | 恢复后的新标识与原备份标识映射，维护关联并识别重复恢复 |

本地数据库是运行中的唯一账务数据来源。统计和预算统一使用流水计算口径，可有可重建缓存，但不得缓存错误的跨币种总金额。

### 验收目标

| 项目 | 建议要求 |
| --- | --- |
| 快速记账 | 至少 5 名目标用户，每人完成 5 笔普通记账，中位数不超过 10 秒 |

| 全离线 | 飞行模式首次启动至本地文件恢复完整可用，没有网络超时等待 |
| 持久化 | 已提交记录在杀进程和重启后不丢失、不重复 |
| 异常恢复 | 事务失败和备份恢复失败整体回滚，保留原数据 |
| 可访问性 | 字体放大不遮挡金额与币种，状态兼用文字、颜色和符号 |

性能测试登记设备、系统版本、数据集和样本量，性能项各至少 100 次有效采样。所有数值均是待验证目标。

## 十四 交付阶段与发布条件

### 阶段一 需求与原型

### 阶段二 单机记账闭环

### 阶段三 备份与可靠性

### 阶段四 发布准备

全部 P0 验收通过，无数据丢失、金额计算错误、币种混算或无法恢复的阻断缺陷。完成实际数据行为核对、隐私说明、帮助与分发材料。

文档完成、开发完成、自动化检查通过、真机验收、平台审核、上架分别记录。本次范围仅为需求设计；尚未实现 App 或验证运行性能。工期需在技术方案、人员与系统支持范围确定后估算。
