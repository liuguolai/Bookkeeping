# 多语言维护说明

界面支持 `zh-CN`（简体中文）、`zh-TW`（繁體中文）和 `en`（English）。首次使用按浏览器或原生 WebView 提供的语言列表选择；繁体地区和 `zh-Hant` 使用繁体，其他中文使用简体。没有支持的系统语言时回退简体。用户在引导页或设置页选择后，以本机选择优先。

语言保存在 `localStorage` 的 `pocket-ledger-language`，不写入账目模型、加密备份或云同步。读写受到浏览器限制时，仍能在当前会话切换。切换通过 React 外部状态订阅刷新，不重载页面或重建记账表单；同源其他标签页通过 `storage` 事件刷新语言。

## 文案维护

- `src/i18n.ts` 提供 `t`、`useLocale`、日期格式化和状态提示翻译。简体原文直接作为键；英文和繁体分别位于 `src/locales/en.json` 与 `src/locales/zh-TW.json`。语言资源随应用构建并离线缓存，不调用在线翻译服务。
- 新文案同时补全两个 JSON。使用 `t('名称：{0}', [name])` 形式保留参数，避免翻译用户输入。带翻译的组件订阅 `useLocale()`；模块顶层常量保留源文案，显示或创建默认值时再调用 `t`。
- 只翻译应用文案。已有账本、分类、支付方式、模板名称及备注不自动翻译或重命名。创建账本时按当前语言保存默认分类和支付方式，之后视为普通可编辑数据。
- 服务器继续返回原协议错误；界面用 `messageText` 翻译已知错误和持久显示的状态，未知错误保留原文。添加服务端错误时同时添加语言资源。
- 使用 `Intl.DateTimeFormat` 处理显示日期；存储日期、时区、币种代码、金额整数精度、备份格式和同步协议保持原有语义。CSV 表头和类型列随导出时的语言变化，用户数据原样导出。

## 验证

`tests/i18n.test.ts` 检查系统语言识别、资源和占位符完整性、日期格式、错误提示、新账本默认数据及已有数据保留。`tests/e2e/i18n.spec.ts` 覆盖桌面和手机的首次语言、三语切换、刷新、记录/草稿保留及主要英文面板。原有中文界面测试显式设置 `zh-CN`，手动创建的第二浏览器上下文也需指定语言。

共享前端代码的验证不等于原生安装包更新或线上部署。已存在的 APK、静态发布包和线上网站需要另行构建或发布才会获得此功能。
